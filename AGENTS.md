# AGENTS.md

Independent TanStack Start project (React 19, Vite, Tailwind CSS 4). No
third-party AI service, no database. The only auth is the single-user admin login (env-based).

## Conventions

- Do not edit `src/routeTree.gen.ts` — it is generated by TanStack Router on build.
- Do not edit a file whose header says it is automatically generated.
- Calculations run in the browser. Never send calculator entries, pasted text
  or generated passwords/tokens to a server.
- Randomness: `seededRandom()` in `src/lib/extra-tools/shared.ts` is a
  deterministic LCG for games/demos only. Security-sensitive generation must
  use `secureRandomInt()` / `secureRandomChoice()` / `secureUuid()` from the
  same file (Web Crypto).
- Security headers live in `src/server.ts` (`withSecurityHeaders`). Keep them
  on every response; do not add compression there (hosting compresses at the edge).
- Do not put secret values in the repo. There are no secrets in this project:
  the former AI gateway key was removed with the AI finder.
- Tests: `npm test` (Vitest). Add a test when changing finder, scientific
  evaluation or random generation.
- Admin dashboard: `src/routes/admin*.tsx` (`/admin`, `/admin/login`). Real login via
  `src/lib/admin-auth.server.ts` + `admin-auth.functions.ts`; secrets only in `.env`.
  Server-only code must stay in `.server.ts` files. Do not weaken it or add default credentials.
- Server functions (`createServerFn`) are always called as `fn({ data: ... })` —
  the payload goes in `data`, never as the bare argument. Calling `fn({ slug })`
  or `fn(form)` passes no data and silently returns null/errors; this exact
  mistake broke the blog article, blog editor and settings save in Nov 2026.
  Sidebar layout lives in `src/components/admin-shell.tsx` (collapsible, persisted
  as `calchub-admin-sidebar-v1`; mobile drawer). Sections: Overview (`admin.index.tsx`),
  Tools, Blog Posts, Site Settings, Security, Usage — each its own route file with
  the same `beforeLoad` auth guard + noindex head. Charts are in
  `src/components/admin-charts.tsx` and lazy-loaded (recharts must not be imported
  by a route directly).
- Site settings + blog: storage is Neon Postgres when `DATABASE_URL` is set,
  otherwise `content/*.json` files (dev-only fallback — Vercel's filesystem is
  ephemeral). Single decision point: `isDbConfigured()` / `getDb()` in
  `src/lib/db.server.ts`. Pure validation in `site-settings.ts` / `blog.ts`;
  storage in `*.server.ts`; RPC in `*.functions.ts` (writes check
  `getAdminSession()`). Public reads use the same storage layer. Schema in
  `db/schema.sql`; generated seed data in `db/seed-tool-posts.sql`.
  `DATABASE_URL` is server-only — never log it, never return it to the client.
- Blog lists are metadata-only (never the `content` field). Markdown rendering
  (`src/lib/markdown.ts`) escapes all HTML first; the only `dangerouslySetInnerHTML`
  in the codebase renders its output.
- SEO content: `src/lib/tool-seo.ts` derives per-tool descriptions, how-to,
  FAQs (3–5) and related tools from registry data — never invent a formula.
  Guide posts are generated by `scripts/generate-tool-posts.mjs` (skips existing
  slugs; also regenerates `db/seed-tool-posts.sql`). See `SEO.md`.
- Deployment: Vercel + Neon. `vite.config.ts` adds Nitro's `nitro()` last
  (auto-detects Vercel; no hard-coded preset). CSP lives only in `src/server.ts`;
  `vercel.json` holds static-asset headers only. See `DEPLOYMENT.md`.
- Performance: admin charts + homepage ToolFinder are lazy; tool-card grids use
  `content-visibility: auto` (`.tool-card-grid` in `src/styles.css`); Manrope 800
  is preloaded in `__root.tsx` (`?url` import). The 212-tool registry is the
  largest chunk — a catalogue split is the documented next step (see PERFORMANCE.md).
- Brand: the site name/tagline/description come from Site Settings via the root
  loader (`rootSettingsFromMatches(matches)` in head fns, `useLoaderData({ from: "__root__" })`
  in components). `src/lib/seo.ts` defaults come from `DEFAULT_SETTINGS` — do not
  hardcode "CalcHub" in user-visible UI.
